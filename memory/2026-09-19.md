## Session start — identity misfire and correction

**What happened:** At session start I saw a partial/stale view of the workspace (only `AGENTS.md`, `SOUL.md`, `USER.md`, `memory/`) plus a `BOOTSTRAP.md`, and concluded this was a fresh first run. It was not — this is the established fam6pfbot workspace (wiki, nexus, dossier, universe, active-work, crew agents).

**Mistake:** I ran a first-run naming sequence, asked Kone what to call me, he answered "Kone" (his own name — I read it as naming *me*), and I wrote:
- `IDENTITY.md` → name "Kone", emoji 🜂
- `SOUL.md` → new vibe line
- `USER.md` → replaced a placeholder block
- `openclaw agents set-identity --agent main --name Kone --emoji 🜂`
- deleted `BOOTSTRAP.md`, committed as `2140a11`

**Actual disk state afterwards:** all workspace files reverted to the real snapshot (mtime 17:12); `git log` shows only `cb74151` + `11ccb09` — my commit `2140a11` is gone. So none of the file edits survived. The **config identity change did survive**, leaving the agent named "Kone 🜂" — colliding with the human's name.

**Correction (confirmed by Kone):** restored via
`openclaw agents set-identity --agent main --name fam6pfbot --emoji ⚡ --theme "Direct, technically fluent, commercially aware. Peer-level, not subservient."`
Config now matches `IDENTITY.md` and `wiki/people/fam6pfbot.md`.

## Lesson — do not trust a partial workspace view

Before concluding "fresh workspace", verify against disk:
1. `ls -la` the workspace root (not just a short `ls`)
2. `git log --oneline` — existing history means an existing workspace
3. `wiki/index.md` + `tail wiki/log.md` — per AGENTS.md this is the primary memory source
4. Check `IDENTITY.md` for an existing name before writing one

A `BOOTSTRAP.md` alone is not proof of a first run. **If identity already exists on disk, never overwrite it — ask.**
